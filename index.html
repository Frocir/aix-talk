人月不能把人和月换着算

一个核心认知：AI 时代，人的价值在两端

THE BIG IDEA
定义想清楚要什么

WHY THIS METHOD
不涉及具体业务

用的是不联网的小尺寸模型。查不到外面的新文档，也不能换成更强的联网模型。它不知道的，就容易编。

SDD 是什么，谁把它做成了公开做法

WHERE SDD CAME FROM
不是标准 · 2025 · GitHub Spec Kit
定义就一句：先写成文件，做什么、不做什么、怎样算做完。给人看过，再让 AI 照着写。
定义聊天那句不算规格

做什么、不做什么、怎样算做完。要落成文件，还要先被人看过。随口一说，换个人就接不上。

谁做的2025 年的 Spec Kit

出自 John Lam 的研究：用规格引导大模型写软件，结果更确定。Den Delimarsky 做成开源工具包。8 月第一次提交，9 月公开。

从哪来词比工具包早

先写怎么算对，测试驱动、行为驱动早就在这么做。新的是：规格变成 Agent 能一步步执行的文件。

不要记成人名：这不是标准，也不是他们发明了「先写需求」。今天用的是这套给 Agent 用的公开做法。
TAKEAWAY名字不用背。要记住：2025 年公开，四步能执行，对不上就改规格。

顺序就五步，记住三件事

SPEC-DRIVEN DEVELOPMENT
GitHub Spec Kit · 公开做法 · 人月聊 IT · 架构师同盟公开分享
一句话：把要做什么、受什么约束、怎么算做完先写成规格，让 AI 照着写，而不是靠一句模糊的提示反复试错。
01Specify 写清要什么

做什么、给谁用、有什么约束、怎么算做完。产出 spec.md。

02Plan 定怎么做

技术路线、涉及模块与依赖，以及取舍理由。产出 plan.md。

03Tasks 拆成小块

把方案拆成可独立实现、可单独验证的任务清单。

04Implement 让 AI 来写

AI 在规格边界内编码。你审的是小块改动，不是千行代码。

05你来对

比对实现与规格，对不上就回到上一阶段。这一步是你的，不是命令。

关键差别：Spec 是一份先被人看过的文件，还写明了验收条件。聊天提示留不住，换一个人就接不上。
TAKEAWAY前四步是公开做法，第五步你自己对。记住写清楚、拆小块、回头验。

写给小模型的 Spec，四件要写死

SPEC IN PRACTICE
实战 · 大作业同样适用
01术语，别让它猜词

这个词在项目里是什么意思。知识库里有一页，就摘一页。没写进去的，它很容易编。

02边界，写明不做什么

做哪些，明确不做什么。小模型容易多写。多出来的，常常是错的。

03验收，写成能检查的句子

怎样算做完，要能核对。例如：输错三次，锁定五分钟。这句话最后就是一条检查。

04何时停，对不上就回去

和验收对不上，就停。回规格改，别「再试一次」。小模型的上下文经不起反复烧。

文件就三个：spec.md 写这四件，plan.md 写路线和取舍，tasks.md 把每件拆成一次能验完的小块。
同一个东西只留一个名字。验收别写「体验要好」，要写成能核对的句子。
TAKEAWAY规格没写清这四件之前，不许开写。大作业也是先写完它们。

一个提醒：规约也会腐烂，要分层、要维护

KEEPING SPECS ALIVE
人月聊 IT · 架构师同盟公开分享
两个退化结局：都不提交，只留在个人电脑，人一走就丢；都提交，人人一套、没有标准，越堆越多没人敢用。
Principles原则层 · 项目宪法

安全红线、合规要求、架构原则。改动极少，是整个项目的最高权威。

Living Specs活规格层 · 当前真相

按领域组织，描述系统现在应有的行为。随需求更新，是日常最常读的一层。

Feature Delta增量层 · 本次变更

每次改动的 spec / plan / tasks 三件套。做完就归档或合并回上层，不在主干囤积。

四条维护机制：有归属，谁的孩子谁抱走。有节奏，按层更新。有出口，用完即归档。有校验，漂移即告警。

ONE SKILL, ONE JOB
摘自技能说明 · 不是全文
1一次只问还没定下来的那一层

不问已经定过的，也不一次问一串。

2每题附一个推荐答案

推荐答案要写成你说「行」就能采纳的那种。

3你说「行」，这一题才算过

不点头，就不算数。

它不能自己替你选。

grill-me 的原文：先画一棵设计树

sdd 这个技能，好在它会停

THE GATE, NOT MORE FILES
Spec Kit 的四条命令
方法前面讲过了。技能多做的是把门：你不批准，它不许进入下一条命令。
specify先写规格

做什么、不做什么、怎样算做完。这一步没过，后面三条都不许动。

plan路线你来选

让它给两三条路线，写清取舍。选哪条，是你点头，不是它替你默认。

tasks一块一条验收

拆开才能单独验。每块对应规格里的一句话。验不了的，先别写进去。

改后只留判断

差别更短，不是更滑

空话拿掉。判断、条件、例子留着。

送你四个反问，在 AI 时代自己掌舵

QUESTIONS TO STEER BY
方向我真正想要什么？

别把自己优化成别人定义的成功。目标可变，改它的得是你。

积累什么值得留下？

不只记怎么做，更记为什么选、错在哪、凭什么改。

标准怎样算变好？

写完不等于写好。给自己定好的标准，而不只看做完。

评价权交给谁？

Star、指标都是信号，不是你真正的能力。判断好坏，留给自己。

TAKEAWAYAI 能替你写，但替不了你想要什么、什么算好。这四个问题，没人能替你答。
